# Internationalization (PT / EN)

The interface comes in two languages. Content lives in two parallel folders:

| What | Portuguese | English |
|---|---|---|
| Interface text, Billy's lines | `js/i18n.js` → `pt` | `js/i18n.js` → `en` |
| Glossary tooltips | `js/glossario.js` | `js/glossario-en.js` |
| Exercises, manifest, Web Lab | `content/*.json` | `content/en/*.json` (same file names) |
| Runner and mock messages/data | `py/runner.py`, `py/mocks_ia.py` (`lang="pt"`) | same files (`lang="en"`) |

The language is chosen in this order: `?lang=pt|en` in the URL, then `config.lang` in the save, then the choice made before any save existed (localStorage `pyai_dojo_lang`, which does not count as a save), then the browser language (`pt*` → pt, anything else → en). Saves from before i18n that have no `lang` stay in pt. Players can switch with the Português / English buttons on the welcome window or with Settings → Language. Switching reloads the page; a switch made from Settings skips the welcome window and returns to the same screen (the URL hash, e.g. `#/ex/<id>`), with the editor draft intact.

`content/en/` is fully translated: every file passes `verify --lang en` (273/273), the Pyodide parity check (273/273) and the Web Lab check (30/30), and `i18n_check.py --estrito` reports 0 structural diffs and 0 Portuguese leftovers. The English `manifest.json` also carries `rotulos_conceitos`, so concept tags show as English labels.

## Translator contract

**Keep identical to PT** (`tools/i18n_check.py` fails the build otherwise):

- File names. In `manifest.json`, everything except the titles.
- Exercise order and ids.
- The set of keys in every exercise and every test.
- `id`, `nivel`, `tier`, `xp`, `conceitos`, `pacotes`, `mocks`, `timeout_s`, `categoria`, `editaveis`, plus the top-level `ato` and `trilha`.
- The counts: exactly 3 `dicas`, and the same number of `testes_visiveis`, `testes_ocultos` and `testes_web`, of `entradas` per test and of `arquivos`.
- The harness API itself. English content uses the **English aliases** of the same objects (the PT names keep working, so PT content is untouched):

  | PT (content/) | EN (content/en/) |
  |---|---|
  | `_verificar`, `_rodar` | `_check`, `_run` (`_stdout`, `_mocks`, `_lang` are shared) |
  | `_mocks.historico_http` | `_mocks.http_history` (the same list) |
  | `_mocks.relogio()`, `_mocks.avancar_relogio(s)` | `_mocks.clock()`, `_mocks.advance_clock(s)` |
  | `_mocks.roteirizar_falhas`, `_mocks.roteirizar_erros_llm` | `_mocks.script_failures`, `_mocks.script_llm_errors` |
  | `_mocks.embed_texto` | `_mocks.embed_text` |
  | `client.chamadas` | `client.calls` (the same list) |
  | http record keys `metodo`, `caminho`, `relogio` | `method`, `path`, `clock` (added when `lang="en"`; `url`, `params`, `json`, `headers` are shared) |
  | web: `_verificar`, `_clicar`, `_texto`, `_esperar` | `_check`, `_click`, `_text`, `_wait` (`doc`, `win` are shared) |
  | LLM error events `"args_invalidos"`, `"multi_blocos"`, `"vetor_zero"` | `"invalid_args"`, `"multi_block"`, `"zero_vector"` (`"rate_limit"` is shared) |
  | web error box `#__dojo_erro` (CSS can style it) | `#__dojo_error` (the runner picks the id by language) |

- Mock constants: host `https://api.dojo.dev`, token `tk_dojo_001`, password `dojo123`.

**Translate:**

- `manifest.json`: `titulo`, `atos[].titulo`, `atos[].niveis[].titulo`, and optionally `rotulos_conceitos` (`{tag: label}`, which the UI shows instead of raw concept tags).
- Top-level `titulo` of each file.
- Per exercise: `titulo`, `explicacao_md`, `enunciado_md`, `dicas[]`, `starter_code`, `solucao_referencia`, every `testes_*[].nome`, every `testes_*[].codigo` (strings and identifiers only) and `testes_*[].entradas` values.
- `arquivos` contents. Fixture names may change, but every reference to them must change too.
- `web_html`/`web_css`/`web_js` and `solucao_*`.

**Renaming identifiers.** A function, class, parameter, variable or dict key that a test touches must be renamed in ONE pass across `starter_code`, `solucao_referencia`, every `testes_*[].codigo` and every `code` span in `enunciado_md`/`explicacao_md`/`dicas` of that exercise. Rename whole words only (`calcular_media` → `average`, never a substring). Strings a test compares against (printed lines, returned messages) must match what the translated solution produces. Re-run the verify after each exercise.

**English mocks** (active when `lang="en"`):

| | PT | EN |
|---|---|---|
| Routes | `/usuarios?pagina=N`, `/produtos/<id>`, `/segredo`, `/erro500`, `/modelos?cursor=` | `/users?page=N`, `/products/<id>`, `/secret`, `/error500`, `/models?cursor=` |
| Unchanged routes | `/status`, `/timeout`, `/echo`, `/login` | same |
| Fields | `erro`, `dados`, `pagina`, `total_paginas`, `nome`, `preco`, `time`, `segredo`, `recebido`, `metodo`, `senha`, `modelos`, `familia`, `custo_por_1k`, `proximo_cursor` | `error`, `data`, `page`, `total_pages`, `name`, `price`, `team`, `secret`, `received`, `method`, `password`, `models`, `family`, `cost_per_1k`, `next_cursor` |
| LLM table | "capital do brasil" → Brasília · "capital da frança" → Paris · olá/oi → "Olá! Como posso ajudar?" · python → "Python é uma linguagem de programação." · else "Você disse: …" · after a tool result "O resultado é ….", system "pirata"/"maiúsculas" | "capital of brazil" → Brasília · "capital of france" → Paris · hello/hi/hey → "Hello! How can I help?" · python → "Python is a programming language." · else "You said: …" · "The result is ….", system "pirate"/"uppercase"/"all caps" |
| RAG | marker `pergunta:` → `{"resposta", "fontes"}`, empty → "não sei" | marker `question:` → `{"answer", "sources"}`, empty → "I don't know" |
| Tools | `somar` ("some A e B"), `clima` {"cidade"} ("clima em X"), `buscar_docs` {"consulta"} ("busque sobre X") | `add` ("add A and B"), `weather` {"city"} ("weather in X"), `search_docs` {"query"} ("search for/about X") |

Exercises that depend on the mock routes, fields or LLM phrases above use the English contract in `content/en/` (their tests and solutions were moved to it during translation).

**Leftover heuristic.** `i18n_check.py` flags frequent Portuguese words and the letters ã/õ/ç. It ignores spellings that are also everyday English (`do`, `no`, `use`, `some`, `todo`), the PT contract names (`embed_texto`, `roteirizar_erros_llm`, `historico_http`, `_texto`, `__dojo_erro`, the mock event names, `.chamadas`; English content should use the aliases above anyway), URLs/e-mails/domains, hex colours and CSS `em` units.

**Glossary.** A `code` span in English prose gets a tooltip only if its token is a key in `js/glossario-en.js`. Add English aliases there (for example `cosine`).
